01系统概览

悦集商城是一套前后端分离、多端一体的电商系统：买家在 H5 或 PC 端逛商品、加购物车、领券下单、模拟支付、申请售后；运营在后台管理商品、订单、售后、优惠券、评价与营销活动；商家在独立的商家中心自助发品、发货、审核售后、结算提现。

02C 端操作（H5 / PC）

H5 与 PC 的购物链路完全一致，仅布局不同。以下操作在两端通用，截图分别给出两端画面。

2.1首页与导航

首页由轮播图与商品推荐卡片组成，是买家进入商城的第一入口。PC 端顶部提供搜索框（带联想与热搜）、购物车角标、我的订单、领券中心与营销专区入口（秒杀 / 拼团 / 抽奖 / 分销中心）；H5 端底部为「首页 / 分类 / 购物车 / 我的」四个主 Tab。

无需登录即可浏览首页、分类、商品列表/详情、领券中心均为公开页面；点进购物车、下单、我的订单等页面时才会跳转登录，登录后自动回到原页面。

2.2分类与商品列表

从首页类目或分类页进入商品列表。列表支持按类目筛选——选择一级类目时自动包含其下所有子类目商品，分页每页最多 60 条。搜索框输入关键词后进入搜索结果页：关键词经过同义词与拼音归一（如搜「shouji」也能命中「手机」），下方展示热搜词，无结果时按类目兜底推荐。

2.3商品详情与 SKU

详情页展示商品主图/轮播图、价格区间、销量、品牌、类目与商品编号。买家必须先选择规格（如「颜色-曜石黑 / 存储-16G+256G」）才能加入购物车或立即购买，不同规格对应各自的价格与库存。

V15 促销展示：商品命中促销活动时，卡片与详情页会出现活动角标（如「满减」「限时折扣」），价格区展示活动价与划线价；限时折扣类活动附带倒计时，活动结束后价格自动恢复原价。

  • 价格在数据库中以「分」存储，页面统一换算为「元」展示。
  • 未选规格时按钮置灰并提示「请先选择规格」；收藏按钮可直接点亮「已收藏」。
  • 商品图加载失败会自动回落到占位图，不影响下单。

2.4购物车

购物车按 SKU 维度记录商品，可修改数量、勾选/取消勾选、删除条目。底部结算栏实时按勾选商品合计金额。V14 购物车营销：临近促销门槛时给出「还差 X 元可用满减券/满减活动」的凑单提示；商品降价时显示降价提醒标；失效商品（下架/删库）自动归入失效分区，不再计入合计。

库存口径加入购物车不占库存，提交订单时才扣减 SKU 库存；若库存不足，提交会被拒绝并提示。

2.5领券与用券

领券中心列出当前可领的券模板（面额、门槛、有效期、剩余数量），点击「领取」即进入「我的优惠券」。下单确认页可选择可用券，系统按门槛自动过滤不可用券。

券的生命周期：领取 → 下单锁定 → 支付核销 / 取消释放。取消或关闭订单时，锁定的券会自动退回可用状态。

2.6下单与模拟支付

  1. 购物车勾选商品 → 点「去结算」，进入确认订单页。
  2. 选择收货地址（可现场新增/修改）、选择优惠券、核对商品明细、运费与应付金额。
  3. V15 优惠试算明细：确认页右侧结算区逐行展示「商品总额 → 各促销活动减免 → 促销优惠合计 → 优惠券 → 运费 → 应付金额」，每一分钱优惠都可追溯（见下图）。
  4. 提交订单：系统扣减库存、锁定优惠券，生成状态为 10 待付款 的订单；促销减免按「最大余数法」分摊到每个订单行。
  5. 进入收银台选择支付渠道（沙箱秒到账；微信 / 支付宝配置商户参数后可用），点「立即支付」，订单变为 20 待发货。金额以服务端核价为准，URL 传参改不了。
  6. 订单完成后可在详情页申请开票，已发货订单可查看分包裹物流轨迹。
超时关单订单 30 分钟未支付，定时任务自动把订单置为 60 已关闭，同时回补库存、释放优惠券；若渠道回调迟到，已关单订单不会被复活，而是自动原路退款。

2.7我的订单

订单列表按状态分 Tab：全部 / 待付款 / 待发货 / 已发货 / 已完成。每张订单卡显示下单时间、订单号、商品缩略图与数量、实付金额，右侧为状态与「订单详情」入口；有售后记录的订单会额外出现「售后」角标。

可执行操作：取消订单（仅待付款）、确认收货（已发货 → 已完成）、申请售后（已发货/已完成）、再次购买。

2.8订单详情与时间线

订单详情聚合收货信息、商品明细、金额构成（商品总额、促销优惠、运费、优惠、实付）与操作时间线。时间线按事件逐条记录操作方与时间，便于售后追溯。

2.9售后申请与查询

售后入口在订单详情页。仅本人订单、状态为 30 已发货 或 40 已完成、且当前无进行中售后单时才可申请。

售后类型规则
1 仅退款货不要了，库存不回补；金额自动带出订单实付，不可修改
2 退货退款货已回，退款时回补库存；金额自动带出订单实付
3 换货 V15审核通过后按页面提示寄回原商品并填写物流单号 → 商家确认收货 → 商家发出换货商品；换货不产生退款
部分退款 V15按订单项勾选并填写退款金额（单价 × 数量为上限）；同一订单可多次申请，累计不可超过实付金额

申请原因必填，凭证图片选填最多 6 张。申请列表与详情见下图。

常见拦截订单状态为 10/20/50/60 时申请会返回「该订单当前状态不支持申请售后」；申请他人订单返回 403；已有进行中售后单需先关闭；部分退款累计金额超过订单实付会被拒绝。

2.10积分与签到

会员每日签到得积分：赠送积分 = min(连续签到天数, 7)，即连签 7 天及以上每天固定 7 分；同一天重复签到会被拒绝。

2.11收藏 / 足迹 / 评价

  • 我的收藏：商品详情页点「收藏」后进入收藏夹，可取消收藏。
  • 我的足迹：浏览过的商品按时间倒序自动记录。
  • 我的评价：已完成订单可对商品打分并写评价；评价内容会聚合到商品详情的均分与列表，增强能力见 2.20。

2.12消息中心

系统通知统一进入站内消息：售后审核结果、退款到账、发货提醒等。消息按时间倒序，未读有红点标记。

2.13地址管理

维护多个收货地址，可新增、编辑、删除与设为默认；下单时默认选中默认地址。

2.14个人中心

「我的」页汇总全部会员能力入口：订单状态快捷入口、消息中心、每日签到、我的积分、我的收藏、收货地址、我的售后、我的足迹、我的评价、我的优惠券、领券中心、分销中心、编辑资料。V14 起支持协议查看、账号注销（7 天冷静期）与个人信息导出。

2.15店铺主页与跨店购物

商品都有归属店铺：平台自营商品归「悦集自营旗舰店」（商家编号 S00000001，id=1），第三方商家的商品在商品卡、详情页与订单上都会显示店铺标，点击即可进入店铺主页查看店铺信息与店内全部在售商品。

跨店拆单规则

  1. 购物车勾选多个店铺的商品点「去结算」，确认页按店铺分组展示，并提示「已选 N 个店铺的商品」。
  2. 跨店订单不支持优惠券：券只能作用于单店订单，确认页的券选择器会被禁用。
  3. 提交订单时系统按店铺拆成 N 笔独立订单（一单一商家），需分别进入收银台逐一支付。
  4. 拆单后自动跳转「我的订单」，逐笔支付；售后同样按店铺分别处理。
资金口径每笔订单确认收货时按商家费率自动分账：平台抽成 = 实付 × 费率(‰)、商家应收 = 实付 − 平台抽成，两者相加恒等于实付金额。平台自营店铺（费率 0）不分账。

2.16限时秒杀

秒杀专场按「进行中 / 即将开始 / 已结束」三段分组展示。进行中的场次显示秒杀价与原价划线、距结束倒计时、进度条（已抢件数）与「去抢购」按钮；即将开始的场次显示开抢时间与「未开始」按钮（点击可收藏提醒，开抢前不可下单）。

防超卖秒杀下单走「Redis 预扣 + 数据库条件更新」双保险；每人限购数量（per_limit）在下单时校验，超限被拒。秒杀订单在「我的订单」中与普通单同流展示（订单类型标记为秒杀单）。

2.17拼团

拼团专区列出进行中的团活动：团价与原价对比、成团人数、成团时限。买家开团支付后进入「我的拼团」分享参团；成团时限内人数凑齐即成团进入发货，超时未成团自动全额退款。

2.18幸运抽奖

抽奖页展示奖池（积分、优惠券、实物）与参与消耗（免参与或扣积分）、每日限抽次数。抽中实物奖品后在「我的抽奖记录」中登记收货信息等待发货；抽中券自动入「我的优惠券」。

2.19分销中心

会员在分销中心申请成为分销员（平台审核后生效），获得专属邀请码 / 邀请链接。通过邀请注册的下级会员下单并确认收货后，按平台配置的佣金规则自动记入佣金流水。分销中心展示累计佣金、已结算、可提现与我的团队，可发起佣金提现（平台审核打款，拒绝原路退回）。

体系独立分销佣金记在「会员分销体系」，与商家分账（货款体系）互相独立；佣金只从推广订单产生，确认收货时结算。

2.20评价增强（V15）

  • 追评：订单完成后 30 天内可对已有评价追加一条追评；详情页以「评价 + 追评」双条带展示，追评带「追评」标注与时间。
  • 有用数：其他会员可点「有用」，同一人对同一评价只计一次（幂等），再次点击取消。
  • 评价标签：写评价时可勾选预置标签（如「物流很快」「质量好」），商品详情页展示标签云与各标签计数，点标签可按标签筛选评价。
  • 晒单图片墙：商品详情聚合全部评价图片，形成晒单图片墙，点击查看大图。

03运营后台操作

后台负责商品、交易、营销与商家的全生命周期管理。左侧菜单为一级手风琴分组（点击展开二级）：经营看板、商品管理、订单管理、会员管理、营销管理、商家管理、交易设置、客服与消息，共 27 个页面。

3.1登录

使用 admin / admin123 登录，需额外输入图片中的算术验证码（如 7-2=? 填 5）。登录态存于浏览器本地，过期或 401 时自动踢回登录页。

3.2工作台与经营看板

3.3商品管理

商品（SPU）

维护商品主数据：商品名称、副标题、商品类目、品牌、主图、轮播图、详情、上下架状态与所属店铺。列表新增「店铺」列展示归属商家，编辑表单可切换商品归属的店铺；归属变更保存后，C 端商品卡与详情页的店铺标即时跟随。列表显示类目路径与品牌名称，操作列为「详情」，右上角可导出。

商品 SKU

SKU 是价格与库存的真正载体：同一 SPU 下可有多个规格组合，每个 SKU 独立维护价格、库存、图片与规格值。

商品类目

树形维护类目层级，支持父子关系与图标。类目会影响 C 端筛选结果（选父类包含全部子类商品）。

轮播图与品牌

图片上传商品主图单图上传、轮播图多图上传，文件落盘到 be/mall-cloud/uploads，后台运行时请勿切换到其他目录，否则历史图片会 404。

3.4订单管理

订单列表可按订单号、会员、状态、下单时间筛选，支持导出。行内提供「详情」；处于可操作状态时额外出现「发货」与「关闭」按钮，点击后弹出操作对话框填写物流/备注。

操作前置状态结果
发货20 待发货→ 30 已发货，写入发货时间，C 端可确认收货
关闭20 待发货→ 60 已关闭，回补 SKU 库存与销量
导出任意按当前筛选条件导出订单台账

订单流转日志

每笔订单的状态变更都留痕（下单、支付、发货、收货、关闭、售后事件），可按订单号精确检索，是排查交易问题的主要依据。

3.5售后审核

售后单由 C 端申请产生，本页做审核与退款处理。列表可按售后单号、订单号、状态、类型、申请日期筛选，右上角「导出台账」。

  1. 状态为 1 待审核 的行出现「审核」按钮，点开弹窗选择「同意」或「拒绝」并填写审核意见。
  2. 同意后状态变为 2 已同意，该行出现「确认退款」按钮（换货单则进入收发货流程，见 5.2）。
  3. 点「确认退款」执行模拟退款：状态置 4 已退款；若类型为退货退款，同一事务内回补库存、回减销量。
  4. V15 部分退款：一单可多次审核退款，累计金额由系统校验不超过实付。
  5. V15 平台介入：商家超过 48 小时未处理的售后单自动进入仲裁队列（惰性扫描，不依赖定时任务）；运营在队列中裁决，可改判金额或强制退款，裁决全程留痕。
  6. 审核/退款/裁决结果同时推送到会员消息中心。
幂等与并发状态迁移全部使用条件 UPDATE（WHERE status = 期望值），受影响行数为 0 即视为并发冲突，界面会提示刷新；重复退款不会二次回补库存。

3.6优惠券

券模板维护面额、使用门槛、发放总量、有效期与每人限领；「领券记录」为发放与核销台账，可看到会员、领取时间、使用订单号与状态。

3.7会员管理

查看会员昵称、手机号、积分、注册时间等；可编辑资料、查看会员消费与积分情况。

3.8评价管理

查看会员评价（星级、内容、图片、追评、标签），支持按商品 ID、评分、状态筛选；可进行商家回复，或隐藏违规评价（隐藏后 C 端评价列表不可见）。

3.9消息与地址

  • 站内消息：查看推送给会员的消息台账（标题、内容、接收人、发送时间、已读状态）。
  • 收货地址：会员地址台账，按会员名检索，便于客服核对收货信息。

3.10商户入驻

第三方商家入驻的全流程管理：提交申请 → 平台审核 → 启用经营 → 停用/驳回。审核通过后商家才会在 C 端「品牌店铺」区块露出，才能发布归属自己的商品。

操作说明

  1. 点「新增入驻申请」填写店铺名、执照主体、联系人、经营类目与抽成费率（千分比，如 100 = 10%）。重复执照号会被拒绝（防重复入驻）。
  2. 新申请状态为 0 待审核；点「详情」查看台账与操作时间线，在详情中执行「审核」。
  3. 审核通过（→ 1 启用中）后，店铺进入 C 端店铺列表；驳回（→ 3 已驳回）需填写原因。
  4. 「停用」（→ 2 已停用）后 C 端立即不可见、不可发品；历史订单与结算不受影响。
状态含义C 端可见可发品
0 待审核申请已提交否否
1 启用中审核通过，正常经营是是
2 已停用平台手动停用否否
3 已驳回审核未通过（附原因）否否
平台自营id=1 的「悦集自营旗舰店」为系统内置店铺，费率 0、不可删除，历史无归属商品与订单自动归入该店（展示为「平台自营」）。

3.11商家结算

订单确认收货时按商家费率自动分账并记入商家余额；本页负责把已出账的明细按期间汇总成结算单并核对明细。

  1. 点「生成结算单」，选择商家与结算期间（起止日期），系统汇总该期间内已确认收货订单的货款与抽成。
  2. 同一订单只会入账一次（订单 + 商家 唯一约束），重复生成不会二次入账；期间内有退款的订单会记入「退款冲减」。
  3. 点「明细」下钻查看每笔订单的实付、费率、商家应收、平台抽成与退款冲减，核对无误后作为对账依据。
资金恒等式实付金额 = 商家应收 + 平台抽成（退款单另行冲减）。列表头实时展示该公式，方便对账。

3.12商家提现

商家从可提现余额发起提现，平台审核后打款；拒绝则金额原路退回余额。审核中的金额会被占用，不能重复提现。

  1. 点「发起提现」，选择商家、输入金额（元）与提现方式（余额 / 微信 / 银行卡）；金额不能超过该商家当前可提现余额，超额会被拒绝。
  2. 提交后状态为 审核中，对应金额立即从可提现余额中占用。
  3. 审核「通过」= 打款（→ 已打款，终态）；「拒绝」填写原因（→ 已退回），金额退回余额可再次提现。
幂等与并发提现审核使用条件更新，重复点击不会二次打款；余额加减全部走数据库原子更新（balance = balance ± n 与 balance ≥ 金额 条件扣减），并发申请不会把余额扣成负数。

3.13运费模板

运费从「恒 0」变为真实计费。一个模板 = 计费方式 + 多条地区规则，解析顺序：商品级绑定 → 店铺级绑定 → 全局默认模板；跨店下单时各订单各承担本店运费。

操作说明

  1. 点「新增模板」选择计费方式：按件（首 N 件首费 + 续件费）、按重量（克，口径相同）、满额包邮（未达门槛收固定首费）。金额单位为元，保存时自动转分。
  2. 在模板内维护地区规则：按省份精确匹配，优先于「全国默认」规则（regionCodes 为空的行）。
  3. 勾选「设为默认」把模板设为全局兜底（同库唯一）；被商品或店铺引用的模板不可删除，需先解除引用。
  4. 商品编辑页可为单个商品绑定模板（mall_goods.freight_template_id），店铺在商家资料上绑定店铺级模板。
计费公式units ≤ 首件 → 首费；否则 首费 + ⌈(units−首件)/续件⌉ × 续费；订单金额 ≥ 包邮门槛时运费为 0。C 端确认订单页实时展示运费与「还差 X 元包邮」提示，实付 = 商品总额 + 运费 − 优惠（券不抵运费）。

3.14发货工作台

发货从「订单上手填单号」升级为独立发货单台账，支持一单多包裹（部分发货）与批量导入；全部发完订单才转「已发货」。

  1. 点「发货」输入订单号，系统带出待发明细（数量、已发、剩余）；本次数量留空 = 发剩余全部。
  2. 快递单号全局唯一，重复会被拒绝（防止两单贴同一面单）。
  3. 「批量导入」粘贴多行 订单号,快递公司,快递单号，逐行校验并返回成功数与错误报告（错在哪一行、什么原因）。
  4. 每发一包生成一条发货单与物流轨迹；部分发货不改变订单状态（仍待发货），最后一包发完才转 30 已发货。
C 端联动订单详情按包裹展示物流轨迹（揽收 → 运输 → 派送 → 签收，演示渠道自动生成）；收货人信息随每个包裹快照留档。

3.15发票管理

一单只能开一张发票，金额恒等于订单实付（前端传了也不采纳）；订单必须「已完成」才能申请。

  1. C 端在订单详情点「申请开票」：个人抬头填姓名，企业抬头必须填 15–20 位纳税人识别号；重复申请被拦截。
  2. 本页队列中点「开票」，粘贴电子发票文件地址后置为已开票；C 端即可查看 / 下载发票文件。
  3. 开错票点「红冲」填写原因（→ 已红冲，原票失效）；售后全额退款会自动红冲发票，无需人工干预。
退款联动退款服务确认退款后经内部接口通知订单域自动红冲该订单发票；红冲失败只告警不阻断退款。

3.16支付流水与对账

支付渠道化：POST /shop/pay/prepay 落支付单 → 渠道回调 /shop/pay/notify/{channel} 验签推进订单。沙箱渠道与真实渠道同构（签名 md5(payNo+交易号+金额+状态+密钥)），微信 / 支付宝未配置商户资质时直接 503，绝不伪造支付成功。

  1. C 端收银台按「渠道可用性」渲染支付方式：沙箱恒可用；微信 / 支付宝配置商户参数后自动亮起。
  2. 回调幂等：同一回调重放只推进一次订单，重复回调按重放应答；金额不一致或验签失败一律 400，已关单订单收到迟到回调会自动原路退款而不复活订单。
  3. 「执行对账」按日把渠道账单与本地成功支付单逐笔比对：多账 / 少账 / 本地多 / 渠道多四类差异进台账，「确认 / 忽略」处置。沙箱下未传账单时按本地镜像对账（差异恒 0），作日常巡检。
接真实渠道在 application.yml 配置 mall.pay.wxpay.* / mall.pay.alipay.* 商户参数并把账单下载定时任务接入对账即可，代码路径无需改动。

3.17促销活动

促销引擎（V13 引入计算内核、V14 提供后台与 C 端试算）支持六类玩法：满减、满折、限时折扣、第二件半价、套装、加价购。每个活动配置生效范围（全场 / 类目 / 商品）、规则参数、起止时间、优先级与是否可叠加；未配置叠加时系统默认取「对买家最优」的单个活动。

  1. 点「新建活动」选择类型并填写规则（金额单位元，自动转分）：满减填门槛与减额；满折/限时折扣填折扣率（90 = 9 折）；第二件半价填折扣率；加价购填门槛与换购价。
  2. 设置优先级（数字小者优先）与「可叠加」；多条可叠加活动按「比例类先算、定额类后算」的固定顺序生效。
  3. 保存后在列表「停用 / 启用」即时生效；C 端商品卡与确认订单页同步展示角标、活动价与试算明细（见 2.3 / 2.6）。
引擎口径满减门槛按活动范围内商品原价小计判定（先打折再满减不蚕食门槛）；任何一步减免不超过当前余额，应付永不为负；活动优惠按「最大余数法」分摊到行，分摊合计恒等于优惠总额。试算、下单、后台预览共用同一段纯函数内核，同参数结果一致。

3.19秒杀 / 拼团 / 抽奖活动管理

三类营销活动在此统一维护（与 C 端 2.16–2.18 对应）。

秒杀活动

选择商品与 SKU，配置秒杀价、场次库存、限购数与起止时间；列表实时显示「已抢 / 剩余库存」。删除已产生秒杀单的活动不影响历史订单。

拼团活动

配置团价、成团人数与成团时限（小时）。成团 / 超时退款自动执行，参团记录可在团详情中追溯。

抽奖活动

3.20分销管理

本页维护分销员台账（审核申请、查看团队与业绩）、佣金规则（按类目/商品配置佣金比例）、佣金流水与佣金提现审核；C 端分销员发起的提现在此打款或驳回。

3.21客服工单

会员在 C 端提交的咨询 / 催促 / 投诉统一进入工单台账。按工单号、标题、订单号检索，按分类（商品咨询 / 订单售后 / 物流 / 支付 / 其他）与状态过滤。

  1. 点「处理」进入工单详情，可查看会员问题全文并回复；首次回复后状态转「已回复」，工单侧同时记录首响时间。
  2. 问题解决后点「关闭」结单（→ 已解决）。
  3. 超过 24 小时未首次回复的工单在进入列表页时自动标记「待处理超时」（惰性置位，不依赖定时任务），顶部统计徽标实时显示超时数，应优先清超时队列。

3.22消息触达

业务事件（支付成功、发货、退款到账、售后审核等）经消息服务统一触达会员：站内信落库到 C 端消息中心；短信走 SPI 通道，未配置短信签名 / 模板时自动降级为仅站内信并发失败流水，绝不阻断主业务。

04商家中心（V14）

商家中心是商家（V10 入驻的第三方商家与自营店）的独立工作台：与运营后台同域名不同路径，独立登录、独立会话、数据强制隔离——商家只能看到和操作自己店铺的商品、订单、售后与资金。

4.1入口与登录

访问 http://localhost:9431/#/merchant/login，用入驻时创建的商家账号登录（演示账号 merchant / 123456）。商家令牌以 Merchant-Token 头单独传递，与平台后台、C 端会员的会话互不顶替；为了防串号，登录商家中心会主动清除同一浏览器的平台后台登录态。

4.2经营概览

登录后第一屏：在售商品数、今日订单、本月成交、待发货四张统计卡 + 待办事项（待发货 / 待审核售后 / 待了解结果单，带数量角标）+ 资金概况（可用余额、累计已结算、平台结算比例）。

4.3商品管理

商家自助发品：新建商品默认归属本店铺（归属不可改，杜绝挂到别家店），维护名称、类目、品牌、主图、SKU 价格与库存后提交；上下架即时生效。列表只展示本店商品。

4.4订单与发货

只展示本店订单（含跨店拆单后归入本店的子单）。商家对待发货订单执行发货（对接 3.14 的发货单体系：支持部分发货、快递单号唯一校验），已发货订单可查看物流轨迹。

4.5售后审核

本店订单的售后单由商家优先处理：审核同意 / 拒绝、换货单确认收货并寄出换货商品。商家 48 小时未处理的售后单会被平台仲裁队列接管（见 3.5），商家侧即时失去处理入口。

4.6结算与提现

商家自助对账与资金操作：查看本店结算单与订单级明细、导出对账单 CSV（逐行订单号、实付、费率、应收、抽成、冲减，平台财务可直接导入核对）、发起提现（金额即时冻结，平台审核打款，驳回原路退回余额）。

数据隔离商家端所有查询经 @MerchantScoped 切面自动追加 merchant_id = 本店 条件；直接构造越权请求（如改 URL 中的 id）会得到 403 并写入越权留痕表。

5.2售后状态机（V15 扩展）

基础流转：1 待审核 → 2 已同意 → 4 已退款、1 → 3 已拒绝、1/2 → 5 已关闭（用户撤销）。库存回补只发生在 2 → 4 且类型为退货退款时。

换货流程（type=3）

1 待审核 → 2 已同意 → 用户寄回 → 商家确认收货 → 商家寄出换货 → 完成。换货不退款；换入 / 换出 SKU 的库存净变化在换货收货确认时一次结清，任何一步取消则不动库存。

部分退款

按订单项申请，同一订单允许多次部分退款，系统校验累计退款 ≤ 订单实付，超限返回业务错误。全额退清时与整单退款同效（发票自动红冲、库存按退货类型处理）。

平台介入（仲裁）

商家 48 小时未处理的售后单由惰性扫描置入仲裁队列（进后台列表页时置位，不依赖定时任务）；运营裁决可维持原判、调整金额或强制退款，裁决结果写时间线并推送双方。

5.3商户与提现状态机

商户：0 待审核 → 1 启用中（审核通过）、0 → 3 已驳回（附原因）、1 ⇄ 2 已停用（启停开关）。每次流转写入 mall_merchant_audit_log 操作时间线。

商家提现：0 审核中 → 1 已打款（审核通过，终态）、0 → 2 已退回（审核拒绝，金额退回余额）。审核中金额占用可提现余额；拒绝对应「退回」，已打款不可逆。分销员佣金提现同构。

5.4工单状态机（V14）

1 待处理 →（客服回复）2 已回复 →（结单）3 已解决；超过 24 小时未首响的待处理单附加「超时」标记（不改变状态，只做看板提示）。

5.5促销引擎口径（V13）

  • 六类玩法：满减 / 满折 / 限时折扣 / 第二件半价 / 套装 / 加价购；规则参数统一存 rule_json。
  • 叠加策略 best（默认，取对买家最优的单活动）与 stack（可叠加集合按「比例类先算、定额类后算、同型按优先级 + ID」固定顺序）。
  • 满减门槛按原价小计判定；每步减免 clamp 到当前余额，应付永不为负。
  • 优惠按「最大余数法」分摊到订单行，Σ行优惠 == 活动优惠总额。
  • 计算内核是纯函数（不查库、不读时钟），C 端试算 / 确认页 / 下单 / 后台预览共用，同参数结果一致。
  • 促销之后才轮到券、积分、运费、会员折扣（等级折扣与包邮次数在下单链路叠加）。

06常见问题

Q1　后台登录提示验证码错误？

验证码为图片算式，需填计算结果（如 7-2=? 填 5）。验证码一次性使用，刷新页面需重新获取。

Q2　H5 页面打不开或白屏？

Vite 仅监听 ::1，请用 http://localhost:9531；另外确认网关 8080 已启动、vite.config.js 代理 /api 指向 8080。

Q3　点「申请售后」提示不支持？

检查订单状态是否为 30/40；待付款(10)、待发货(20)、已取消(50)、已关闭(60) 均不支持。同时确认该订单没有进行中的售后单（状态 1 或 2）。

Q4　退款后库存没变？

只有退货退款类型在置为「已退款」时回补库存；「仅退款」表示货不退回，因此不回补，这是设计口径。换货的库存净变化在换货收货确认时一次结清。

Q5　订单一直停在待付款？

30 分钟后自动关单（状态 60），库存与优惠券自动恢复。若需要立即关闭，可在后台订单页对「待发货」订单执行「关闭」。

Q6　页面图片全是占位图？

依次检查：后端 upload 目录是否有文件 → 三端代理是否包含 /uploads、/img → 网关白名单是否放行 /uploads/**。

Q7　后台某页面空白或 404？

后台是 hash 路由，正确地址形如 http://localhost:9431/#/mall/product/mall_goods/list；按表名猜路由会 404。菜单按业务分组：dashboard / product / order / member / marketing / merchant / trade / service。

Q8　跨店下单为什么不能用优惠券？

券作用于单笔订单，而跨店购物会按店铺拆成多笔订单，无法把一张券公平地分摊到多个商家，因此跨店订单统一禁用优惠券。只勾选同一店铺的商品结算即可正常用券。促销活动（满减等）由引擎按行分摊，跨店不受此限。

Q9　商家可提现余额为什么比「商家应收」合计少？

可提现余额 = 累计入账 − 退款冲减 − 提现占用。审核中的提现单会临时占用余额（拒绝后自动退回），结算单只统计已确认收货订单，期间内有退款会记入「退款冲减」列。

Q10　停用的店铺商品还在订单里，售后找谁？

停用只影响 C 端可见性与新发品，历史订单的履约与售后不受影响；涉及该店的分账仍按原费率正常执行，售后处理转入平台（仲裁队列兜底）。

Q11　为什么确认订单页有「促销优惠合计」，而我的订单没有？

促销减免按活动规则在下单时生效并分摊到订单行，不单独退现；若订单未命中任何活动（不在范围、未到门槛、活动已停用）则无此行。核对口径见 5.5：门槛按原价小计判定。

Q12　评价点了很多次「有用」为什么只 +1？

「有用」按 评价 + 会员 唯一键幂等，同一人对同一评价只计一次；再次点击是取消。追评需在订单完成后 30 天内发起，超期入口自动隐藏。

Q13　部分退款提示金额超限？

同一订单所有退款单（含历史已退）累计不能超过订单实付金额。可先查看订单详情中的退款记录，确认剩余可退空间后再申请。

Q14　商家后台登录后，平台后台为什么掉线了？

两套会话虽互不顶替（token 分别存 token 与 merchantToken），但为防串号，登录商家中心会主动清除平台后台登录态，属预期行为；处理完商家事务重新登录平台后台即可。

Q15　商家为什么看不到别的店铺的订单？

这是 @MerchantScoped 数据隔离切面在起作用：所有商家端查询强制限定本店数据；构造越权请求返回 403 并留痕。商家只能处理本店订单与售后。

Q16　工单一直显示「待处理超时」？

该标记表示工单提交后超过 24 小时未获得首次回复。回复一次即记录首响时间、标记自动消除；建议按后台徽标数量优先清理超时工单。
