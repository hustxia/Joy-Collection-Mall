# 商城（mall）V8 规划——秒杀 / 拼团 / 抽奖（交易型营销玩法）

> 版本定位：在 V7「会员互动」（评价/收藏/积分/签到/通知）之上，补齐三类**交易型**营销玩法，形成「互动 + 交易」营销闭环。
> 规划日期：2026-11-01 实盘。服务归属原则沿用 V7：营销玩法统一归属 `mall-marketing`（8205），会员资产（积分/优惠券发放）走 `member` 的 `/inner` 契约，订单与库存复用 `order` / `goods` 既有链路。

## 一、目标

1. **秒杀**：限时、限量、低价抢购；解决高并发下的库存超卖、重复购买、流量削峰。
2. **拼团**：多人成团享折扣；解决成团状态流转、库存预占与失败退款回补。
3. **抽奖**：概率中奖（积分 / 优惠券 / 实物 / 谢谢参与）；解决奖品限量防超发、每人每日限次、中奖后权益发放。
4. 三类玩法均覆盖 **C 端三端（H5 / PC / 后台）**，其中 **PC（mall-pc）按用户要求与后端同步开发**（与 V7 一致）。

## 二、现状盘点（2026-11-01 实测）

- **架构就位**：6 服务 + 网关微服务已上线；`mall-marketing`（8205）已有优惠券全套范式（`MallCoupon*` 实体/服务/控制器：C 端 `ShopCoupon` + 后台 `MallCoupon` + 内部 `InnerMarketing`），新玩法直接复用此范式。
- **可复用能力**：
  - `order`（8204）已有下单 / 模拟支付 / 超时关单；`refund`（8206）已有七态状态机 + `restoreStock` 库存回补补偿——**拼团失败退款、抽奖实物发货**直接复用。
  - `goods`（8202）已有 `restoreStock` / `releaseByOrder` 显式补偿——**秒杀/拼团库存预占与回补**复用。
  - `member`（8203）已有 `/inner/point/grant`、`/inner/notice/push`（V7）——抽奖发积分、拼团成功/失败消息复用。
- **关键约束 ⚠️**：当前后端**未引入 Redis**（grep `RedisTemplate` 全仓为空，docker-compose 仅 mysql）。秒杀高并发依赖原子扣减，因此本版本**P0 决策引入 Redis**（compose 加 redis 服务 + `spring-boot-starter-data-redis` + Lua 原子预扣 + 库存预热 + 令牌桶限流）；并明确**降级方案**：Redis 不可用时退化为 DB 乐观锁（`UPDATE ... SET stock=stock-1 WHERE stock>0`）+ 应用层令牌桶，保证本机无 Redis 也能跑通主流程。
- **前端现状**：PC 已有 18 个页面（含优惠券中心/我的券），H5/后台同构；三类玩法需在首页增加专区入口并新增详情/记录页。

## 三、范围

### P0（交易玩法核心，必做）
- **秒杀**：活动配置（商品/秒杀价/总量/限购/起止）、库存预热、抢购（Lua 原子预扣 → 落单）、防超卖、防重复购买、支付成功后真实扣库存。
- **拼团**：开团 / 参团、成团状态机（拼团中 → 成功 / 失败）、成团时限、库存预占与失败退款回补、我的拼团。
- **抽奖**：活动 + 奖品池（权重/概率/限量）、抽奖（权重随机 + 限量原子扣减）、每人每日限次、中奖记录与权益发放（积分 / 优惠券 / 实物）。
- **基础设施**：Redis 引入（compose + starter），秒杀库存预热与回收。

### P1（管理端与前端）
- **后台管理**：秒杀 / 拼团 / 抽奖三类活动的 CRUD + 数据看板（参与数、成团率、中奖率、库存消耗）。
- **前端三端**：PC 与 H5 首页专区 + 详情/记录页；后台活动管理菜单（走 `sys_menu`）。
- **风控**：秒杀限购（唯一键 `member+activity`）、拼团防重复参团、抽奖日限与防刷。

### P2（看余量）
- 定时任务：拼团超时扫描（`mall-group_team` 仍拼团中且 `expire_time<now` → 批量失败退款）、秒杀结束库存回收。
- 活动模板（复制历史活动）、抽奖「保底必中谢谢参与」策略配置、实物奖品发货单对接 `order`。

### 明确不做
- 分销 / 裂变、跨境多币种、实时大屏、第三方真实支付对接（仍模拟支付）。
- 秒杀与现有优惠券的叠加抵扣（本期互斥，P2 再议）。

## 四、数据模型（db/v8-promo.sql，compose 挂载 07 号位）

> 规范同 V7：审计六件套、每列 COMMENT、唯一键带 `deleted`。会员资产（积分/优惠券）余额不落新表，复用 `mall_member.points` 与 `mall_coupon_record`。

**秒杀**
```sql
mall_seckill_activity  -- 活动：goods_id, sku_id, origin_price, seckill_price, total_stock, per_limit, start_time, end_time, status(0未开始1进行2结束)
mall_seckill_record    -- 参与记录：activity_id, member_id, order_id, sku_id, UNIQUE(member_id, activity_id, deleted) 防重复
```
**拼团**
```sql
mall_group_activity  -- 活动：goods_id, sku_id, group_price, group_size(成团人数), valid_hours(成团时限), start_time, end_time, status
mall_group_team     -- 团：activity_id, leader_id, current_size, status(0拼团中1成功2失败), expire_time
mall_group_member   -- 团成员：team_id, member_id, order_id, is_leader
```
**抽奖**
```sql
mall_lottery_activity  -- 活动：daily_limit(每人每日次), start_time, end_time, status, consume_points(参与消耗积分,0=免费)
mall_lottery_prize     -- 奖品：activity_id, prize_type(0积分1优惠券2实物3谢谢参与), name, weight, stock(-1无限), level
mall_lottery_record    -- 记录：member_id, activity_id, prize_id, is_win, receive_status, order_id
```

**并发/一致性要点（落地时必读）**
- 秒杀库存：Redis 预扣（`DECR` Lua 原子，返回≥0 才放行）→ 建单；DB 双重保险 `UPDATE ... SET available_stock=available_stock-1 WHERE id=? AND available_stock>0`（影响行数=0 即售罄回滚 Redis）。
- 拼团库存：开团/参团时 goods 真实库存**预占**（新增 `/inner/goods/reserve`），成团成功才真实扣减，失败 `restoreStock` 回补（复用现有补偿，避免中间层被 NOT NULL 杀死，见坑库 mysql.md）。
- 抽奖限量：奖品 `stock>-1` 时用 Redis/Lua 原子扣减，DB 乐观锁兜底；日限用 `member_id+activity_id+date` 计数（Redis `INCR EXPIRE` 或 DB 记录）。

## 五、接口设计

### C 端（网关路由新增，`/shop/**`）

| 服务 | 路由 | 接口 |
|---|---|---|
| marketing | `/shop/seckill/**` | `GET /shop/seckill/activities`（进行中+预告）· `GET /shop/seckill/{id}`（详情+剩余库存+是否已购）· `POST /shop/seckill/{id}/buy`（抢购→建 order，幂等） |
| marketing | `/shop/group/**` | `GET /shop/group/activities` · `GET /shop/group/{id}` · `POST /shop/group/{id}/open`（开团）· `POST /shop/group/team/{teamId}/join`（参团）· `GET /shop/group/my` |
| marketing | `/shop/lottery/**` | `GET /shop/lottery/activities` · `POST /shop/lottery/{id}/draw`（抽奖）· `GET /shop/lottery/my` · `GET /shop/lottery/my/remain`（今日剩余次数） |

商品详情 `GET /shop/goods/{id}` 返回体追加 `seckill`（进行中活动价/库存）、`group`（拼团价/已成团数）标志位（登录态）。

### 后台（网关路由新增，`/mall_*`）

| 服务 | 路由 | 接口 |
|---|---|---|
| marketing | `/mall_seckill/**` | `POST /mall_seckill/page` · `POST /mall_seckill/save` · `POST /mall_seckill/close` |
| marketing | `/mall_group/**` | `POST /mall_group/page` · `POST /mall_group/save` · `POST /mall_group/team-page`（团台账） |
| marketing | `/mall_lottery/**` | `POST /mall_lottery/page` · `POST /mall_lottery/save` · `POST /mall_lottery/prize-save` |

### 内部契约（`/inner`，不经网关）
| 提供方 | 接口 | 消费方 |
|---|---|---|
| order | `POST /inner/order/create-promo`（order_type 标记 秒杀/拼团/抽奖实物） | marketing（建单） |
| goods | `POST /inner/goods/reserve`（预占）· `POST /inner/goods/restore`（回补，复用 `restoreStock`） | marketing（拼团库存） |
| member | `POST /inner/point/grant`（已有）· `POST /inner/coupon/grant`（新增，复用 coupon 契约）· `POST /inner/notice/push`（已有） | marketing（抽奖发权益、拼团消息） |
| refund | `POST /inner/refund/batch-create`（拼团失败批量退款，复用状态机 + `restoreStock`） | marketing（定时任务） |
