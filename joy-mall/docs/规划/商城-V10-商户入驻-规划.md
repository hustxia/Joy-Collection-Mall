# 商城（mall）V10 规划——商户入驻 / 多商家平台（B2B2C）

> 版本定位：把「单店自营」升级为「多商家入驻平台」。V8（交易型营销/转化）、V9（分销裂变/拉新）都是在**单店、平台统一收款**的模型上做上层玩法；V10 是它们的**地基反向补强**——一旦商品/订单带上 `merchant_id`，V9 的分销佣金与 V10 的商家货款结算将在同一笔订单上**叠加分润**（见 §3 决策点），平台抽成成为两级分润的统一出口。
> 规划日期：2026-11-01 实盘。
> ⚠️ **架构决策**：商户入驻是一个清晰业务域（商家主体 + 店铺 + 结算），与现有 6 服务的职责不重叠，**建议新建 `mall-merchant` 服务（端口 8207）**，不污染 goods/order/member。新建服务需同步改网关路由、compose 挂载号位、Feign 静态地址清单（详见 §5、§7）。
> ⚠️ **兼容性**：现有 8 张商品、订单等历史数据全部为平台自营，V10 通过 `merchant_id` 默认值 `1`（系统保留的「平台自营店铺」）向后兼容，不破坏任何既有查询。

## 一、目标

1. **商家入驻**：商家提交资质（营业执照/经营类目/联系人）→ 平台审核 → 启用，生成专属店铺。
2. **商品归属**：商品绑定 `merchant_id`，C 端按店铺聚合展示、下单时按商家拆单。
3. **货款结算**：订单完成后平台从实付中按 `settle_rate` 抽成，剩余结算给商家可提现余额；生成结算单与明细。
4. **商家提现**：商家对可结算余额发起提现，平台审核打款（本期仍模拟打款）。
5. **三端覆盖**：后台商家管理（审核/结算/提现）、PC 与 H5 展示店铺（店铺首页 + 商品带店铺标），其中 **PC（mall-pc）按用户要求与后端同步开发**（同 V7/V8/V9）。

## 二、现状盘点（2026-11-01 实测）

- **单店自营现状（已确认）**：`audit/yueji_mall-dump.sql` 中
  - `mall_goods`（255 行）**无** `merchant_id` / `store_id` / `seller` 字段，历史 8 条商品均平台自营。
  - `mall_order`（340 行）**无** `merchant_id`，仅 `pay_order_no` 关联支付单；存在 `mall_order_item`（订单项，结算维度载体）。
  - `mall_member` 无商家关联字段。
  - → 结论：**当前是纯平台自营，商户入驻=为商品/订单补 `merchant_id` + 新建商家/结算域**。
- **可复用能力**：
  - `system`（8201）已有 `sys_menu` 菜单体系、后台用户/审核范式 → 商家审核/店铺管理菜单直挂。
  - `order`（8204）下单 / 模拟支付 / 超时关单 / 已完成钩子 → **结算触发点**复用其「订单完成」事件。
  - `goods`（8202）已有 `/inner/goods/*` 契约范式 → 商品归属校验、按商家查商品复用。
  - `refund`（8206）七态状态机 + `restoreStock` → 退款时冲减商家应收 / 平台抽成复用其钩子。
  - `member`（8203）积分/通知 `/inner` 契约 → 商家入驻通知、审核结果通知复用。
- **关键约束（同 V8/V9）**：后端**未引入 Redis**（高并发抢购才需要）；商户入驻无秒杀级并发，DB 事务 + 唯一键足够，Redis 非 P0。
- **与 V9 的关系（重要）**：V9 在 `mall_order` 上加 `distributor_id`（分销员归因），V10 加 `merchant_id`（商家归属），两列**相互独立、并行叠加**于同一订单；分润叠加规则见 §3 决策点。

## 三、范围

### P0（入驻与结算核心，必做）
- **商家入驻申请**：提交店铺名/经营类目/联系人/营业执照号与照（URL）、结算费率 `settle_rate`（默认平台全局值，可谈）。
- **入驻审核**：待审 → 启用 / 驳回（驳回带原因）；生成 `merchant_no`。
- **商品归属**：`mall_goods.merchant_id` 落库；商家仅能管理自己 `merchant_id` 的商品（goods 服务校验）。
- **拆单 / 订单归属**：购物车结算按 `merchant_id` 分组生成多个 `mall_order`（一单一商家）；`mall_order.merchant_id` + `mall_order_item.merchant_id` 冗余落库。
- **货款结算**：订单完成（确认收货/超时自动完成）后触发 → 生成结算明细（商家应收 = 实付 − 平台抽成 − 退款冲减）+ 累加商家 `account_balance`（可结算余额分）。
- **平台抽成**：`mall_merchant.settle_rate`（‰）默认值来自 `sys_config` 全局；结算原子计算，唯一键 `order_id + merchant_id` 防重复结算。

### P1（管理端与前端）
- **后台（mall-web）商家管理**：入驻审核列表/详情、店铺列表/启用停用、结算账单（按周期聚合）、结算明细、提现审核、数据看板（商家数 / GMV / 平台抽成 / Top 商家）。
- **前端三端（PC 优先同步）**：店铺首页（店铺信息 + 店内商品列表）、商品/订单展示店铺名与「店铺」标、购物车结算时「按店铺分别下单」提示。
- **风控**：商家只能操作自身商品/订单（goods/order 的 `/inner` 校验 `merchant_id` 归属）；结算防重复（唯一键）；退款冲减结算（复用 `refund`）。

### P2（看余量）
- **商家独立后台**（独立登录/子账号/商家自己管商品与订单）—— 本期先做「平台代运营」模式（后台管所有商家），独立商家后台留 V11。
- 结算周期自动化（按日/周/月批量出结算单，本期可手动触发）。
- 商家等级 / 类目费率差异化。
- 真实分账到微信/银行卡（仍模拟）。

### 明确不做
- 商家子账号与独立商家后台登录体系（V11）。
- 平台资金托管 / 担保交易（资金仍走模拟支付）。
- 跨境 / 多币种结算。
- 真实打款（仍模拟审核打款）。

### 决策点（落地前需与产品确认）
- **分润叠加规则**：一笔带分销的订单，平台抽成 vs 分销佣金由谁出？推荐「商家承担分销佣金，从商家应收扣除；平台抽成从剩余实付扣除」（即先扣分销、再扣平台），或「分销佣金从平台抽成中支出」。V10 规划默认**商家承担分销佣金**，但需在 V9/V10 联调时敲定列口径（影响 `mall_commission_record` 与 `mall_merchant_bill_detail` 的勾稽）。
- **一单多商家策略**：确认采用「购物车按商家拆多单」（推荐，结算简单）还是「一单多商家 + 按 item 分组结算」（体验好但退款/支付复杂）。V10 默认**拆多单**。

## 四、数据模型（db/v10-merchant.sql，compose 挂载 09 号位）

> 规范同 V7/V8/V9：审计六件套、每列 COMMENT、唯一键带 `deleted`；金额单位为**分**。

**商家主体**
```sql
mall_merchant          -- 商家：merchant_no(UNIQUE), name(店铺名), legal_name(执照名称),
                        license_no(执照号), license_img, contact_name, contact_phone,
                        category(经营类目), settle_rate(平台抽成‰, 默认全局),
                        status(0待审1启用2停用3驳回), reject_reason,
                        account_balance(可结算余额分), settled_total(累计已结算分),
                        create_time ... 审计六件套
mall_merchant_audit_log-- 审核流水：merchant_id, action(0提交1通过2驳回3停用4启用),
                        operator, remark, create_time
```

**结算与提现**
```sql
mall_merchant_settlement -- 结算单：settlement_no(UNIQUE), merchant_id, period_start, period_end,
                           order_count, goods_amount(商家应收分), platform_fee(平台抽成分),
                           refund_amount(退款冲减分), actual_amount(实际结算分),
                           status(0待结算1已结算), settle_time
mall_merchant_bill_detail-- 结算明细：settlement_id, order_id(UNIQUE 幂等), merchant_id,
                           goods_amount, platform_fee, refund_flag(0否1是冲减)
mall_merchant_withdrawal -- 商家提现：merchant_id, amount(分), method(0余额1微信2银行卡),
                           status(0申请1审核中2已打款3拒绝), audit_by, create_time
```

**商品 / 订单归属（幂等 ALTER，历史数据回填 merchant_id=1）**
```sql
ALTER TABLE mall_goods      ADD COLUMN merchant_id BIGINT NOT NULL DEFAULT 1 COMMENT '商家ID：1=平台自营店铺' AFTER brand_id;
ALTER TABLE mall_order      ADD COLUMN merchant_id BIGINT NOT NULL DEFAULT 1 COMMENT '商家ID：1=平台自营店铺' AFTER member_id;
ALTER TABLE mall_order_item ADD COLUMN merchant_id BIGINT NOT NULL DEFAULT 1 COMMENT '商家ID：1=平台自营店铺' AFTER order_id;
```

**一致性要点（落地时必读）**
- 历史数据迁移：ALTER 后执行 `UPDATE mall_goods/mall_order/mall_order_item SET merchant_id = 1 WHERE merchant_id IS NULL OR merchant_id = 0;` 保证全量归平台自营店铺。
- 结算幂等：`UNIQUE(order_id, merchant_id, deleted)`，订单完成事件重复到达直接返回，避免重复结算。
- 拆单：购物车结算服务按 `merchant_id` 分组，每组生成一个 `mall_order` + 对应 `order_item`，各自独立支付与物流；不跨商家合并支付。
- 退款冲减：复用 `refund` 七态钩子，退款完成回调 `merchant` 对对应 `bill_detail` 标记 `refund_flag=1` 并冲减 `account_balance`（按比例冲减 goods_amount 与 platform_fee）。
- 归属校验：goods/order 的写操作经 `/inner` 校验 `merchant_id == 当前操作商家`，防止越权改他人商品。

## 五、接口设计

### 新建服务归属
- **`mall-merchant`（8207）**：商家入驻/审核、店铺、结算、提现的全部 C 端与管理端接口，以及被 order/refund/goods 调用的 `/inner` 契约。
- 需在：网关 `routes` 新增 `/mall_merchant/**` 与 `/shop/merchant/**`；compose 新增 `mall-merchant` 容器（09 号位）；`mall-common` 的 Feign 静态地址清单新增 `8207`。

### C 端（网关路由新增，`/shop/**`）

| 服务 | 路由 | 接口 |
|---|---|---|
| merchant | `/shop/merchant/**` | `GET /shop/merchant/{id}`（店铺信息/店内商品分页）· `GET /shop/merchant/shop-page`（店铺首页） |

商品列表/详情 `GET /shop/goods/*` 返回体追加 `merchant`（店铺名 + id + logo），订单详情追加 `merchantName`。

### 后台（网关路由新增，`/mall_merchant/**`）

| 服务 | 路由 | 接口 |
|---|---|---|
| merchant | `/mall_merchant/**` | `POST /mall_merchant/page`（入驻列表）· `POST /mall_merchant/audit`（审核通过/驳回）· `POST /mall_merchant/enable` · `POST /mall_merchant/disable` |
| merchant | `/mall_merchant_settlement/**` | `POST /mall_merchant_settlement/page` · `POST /mall_merchant_settlement/settle`（手动/周期结算）|
| merchant | `/mall_merchant_withdrawal/**` | `POST /mall_merchant_withdrawal/page` · `POST /mall_merchant_withdrawal/audit`（审核打款）|

### 内部契约（`/inner`，不经网关）
| 提供方 | 接口 | 消费方 |
|---|---|---|
| merchant | `GET /inner/merchant/info/{id}`（取店铺名/logo，下单与展示用）· `POST /inner/merchant/settle`（订单完成结算入账，幂等）· `POST /inner/merchant/refund-adjust`（退款冲减） | order（结算触发）、goods（展示）、refund（冲减） |
| order | `POST /inner/order/completed`（订单完成通知 merchant 结算，已有「完成」事件复用） | merchant（结算） |
| goods | `POST /inner/goods/check-merchant`（校验商品归属商家，写操作鉴权） | merchant / 后台（越权防护） |
| refund | 复用七态状态机钩子，退款完成后回调 merchant 冲减应收 | merchant（冲减） |
| member | `POST /inner/notice/push`（已有，审核结果/入驻通知） | merchant（通知） |
