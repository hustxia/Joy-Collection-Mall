# 商城（mall）V9 规划——分销裂变 / 社交电商

> 版本定位：在 V7「会员互动」（评价/收藏/积分/签到/通知 → **留存**）与 V8「交易型营销玩法」（秒杀/拼团/抽奖 → **转化**）之上，补齐「**拉新 / 裂变**」环节，形成 AARRR 增长闭环（获取 → 激活 → 留存 → 转化 → 推荐）。
> 规划日期：2026-11-01 实盘。服务归属原则延续 V8：分销核心是「关系链 + 佣金结算」，统一归属 `mall-marketing`（8205）；会员资产（积分/佣金余额）走 `member` 的 `/inner` 契约；订单归因复用 `order`；推广标记复用 `goods`；退款回退复用 `refund` 七态状态机。
> ⚠️ **合规红线**：分销在中国法域下有传销风险，本期**仅做一级分销**（最多二级且需显式开关封顶），杜绝入门费、团队计酬、多级返利。

## 一、目标

1. **分销员体系**：会员申请成为分销员，生成专属邀请码 / 推广链接 / 分享海报。
2. **社交裂变**：被邀请人通过链接/码注册或首单绑定上级分销员，形成可追踪的拉新关系链。
3. **佣金引擎**：按规则（商品比例 / 全局默认比例）在成交后自动计算佣金；订单完成后结算到分销员可提现余额。
4. **合规优先**：仅一级分销（预留二级封顶开关，默认关闭），无入门费、无团队计酬。
5. **三端覆盖**：C 端分销中心（H5 / PC）、后台分销管理，其中 **PC（mall-pc）按用户要求与后端同步开发**（同 V7/V8）。

## 二、现状盘点（2026-11-01 实测）

- **架构就位**：6 服务 + 网关微服务已上线；`mall-marketing`（8205）已有优惠券 / 秒杀 / 拼团 / 抽奖全套范式（`MallCoupon*`、`MallSeckill*`、`MallGroup*`、`MallLottery*` 实体/服务/控制器），分销模块直接复用此范式。
- **可复用能力**：
  - `member`（8203）已有 `InnerMemberController`（`/inner/point/grant`、`/inner/notice/push`）+ `mall_member.points` + `mall_member_point_log` 积分流水（V7）——**佣金提现转增积分、下级绑定/成交通知**直接复用。
  - `order`（8204）已有下单 / 模拟支付 / 超时关单 + `mall_order.order_type`——**分销归因列 `distributor_id` 在其上幂等 ALTER**。
  - `goods`（8202）已有库存与推广标记位——**推广商品标记**复用。
  - `refund`（8206）已有七态状态机 + `restoreStock` 库存回补——**退款时佣金失效 + 余额回退**复用其钩子。
- **关键约束 ⚠️（同 V8）**：当前后端**未引入 Redis**（grep `RedisTemplate` 全仓为空）。但分销**无高并发抢购**，DB 唯一键 + 乐观锁足够，**Redis 非 P0 必须**；若 V8 已引入 Redis 则复用做邀请码缓存 / 分享计数即可。
- **数据落点**：`mall_member` 仅有 `points`（积分）列，**无 money 余额列** → V9 新增 `mall_member.commission_balance`（佣金余额，分）作为佣金落点；提现审核通过后扣减该列（仍模拟打款，可选转增积分复用 V7 体系）。
- **前端现状**：PC 已有 18+ 页面，H5/后台同构；分销中心为新增模块，PC 与后端同步开发。

## 三、范围

### P0（分销核心，必做）
- **分销员入驻**：申请 → 审核 → 启用；生成专属 `invite_code`（唯一）+ 推广链接。
- **邀请关系绑定**：被邀请人通过链接/码注册或首单绑定上级；**防自邀、防冒领、绑定后不可改**（唯一键 `invitee_id`）。
- **订单归因**：下单携带 `distributorId` → `mall_order.distributor_id`；记录推广来源。
- **佣金规则**：按商品比例 / 全局默认比例；成交后生成**待结算**佣金记录（幂等唯一键 `order_id + distributor_id`）。
- **佣金结算**：订单完成（确认收货 / 超时自动完成）后由待结算 → 已结算，累计到分销员可提现余额。
- **合规开关**：配置 `distributor_level_max=1`（默认一级，预留二级封顶位，开启需显式确认合规）。

### P1（管理端与前端）
- **后台管理**：分销员审核/列表/启停、佣金规则配置、佣金明细、提现审核、数据看板（拉新数 / 成交数 / 佣金总额 / Top 分销员）。
- **前端三端**（PC 优先同步）：分销中心首页（邀请码/链接/海报 + 余额 + 团队 + 佣金概览）、推广商品列表（带佣金标签）、我的团队、佣金明细、提现申请、分享海报（前端 canvas 合成二维码 + 商品图）。
- **风控**：邀请关系防自邀/防篡改；佣金防重复计算（唯一键）；退款时佣金回退（复用 `refund` 状态机 + 佣金记录置失效）。

### P2（看余量）
- 二级分销封顶（需显式开启，且严格满足合规：无入门费、仅两级、无团队计酬）。
- 海报后端合成（二维码 + 商品图，默认前端 canvas 生成，后端仅回传分享链接）。
- 分销员等级与升级（业绩阈值）、专属分销价（推广价 vs 零售价）。
- 提现对接真实微信 / 银行卡（仍模拟）。

### 明确不做
- 多级分销 / 团队计酬（涉传销合规红线，本期仅一级，二级需显式开关且封顶）。
- 直播 / 社区 / 内容种草（留 V10+）。
- 真实支付与真实打款（仍模拟）。

## 四、数据模型（db/v9-distribution.sql，compose 挂载 08 号位）

> 规范同 V7/V8：审计六件套、每列 COMMENT、唯一键带 `deleted`。会员资产（积分/佣金）余额不重复建大表，佣金落点用 `mall_member.commission_balance` + 流水 `mall_commission_record`。

**分销员与关系**
```sql
mall_distributor       -- 分销员：member_id(UNIQUE), invite_code(UNIQUE), level, status(0待审1启用2停用),
                         parent_id(上级分销员, 一级为 NULL), total_commission(累计), settled(已结算),
                         withdrawable(可提现), create_time
mall_invitation        -- 邀请关系：inviter_id, invitee_id(UNIQUE 防重复绑定), channel(来源), bind_time,
                         order_count, contribution(贡献成交额), level(第几级)
```

**推广与素材**
```sql
mall_promotion_goods   -- 推广商品：goods_id(UNIQUE), distributor_id, promo_price(推广价,分),
                         commission_rate(佣金比例‰), status
```

**佣金与结算**
```sql
mall_commission_rule   -- 佣金规则：scope(0全局1商品), goods_id, rate(比例‰), fixed(固定分), level, status
mall_commission_record -- 佣金记录：distributor_id, order_id(UNIQUE 幂等), member_id(下单人), goods_id,
                         amount(佣金分), rate, status(0待结算1已结算2失效), settle_time
mall_withdrawal        -- 提现：distributor_id, amount, method(0余额1微信2银行卡), status(0申请1审核中2已打款3拒绝),
                         audit_by, create_time
```

**订单 / 会员归因（幂等 ALTER，同 V8 做法）**
```sql
ALTER TABLE mall_order  ADD COLUMN distributor_id BIGINT      NULL COMMENT '分销归因：带来此单的分销员ID' AFTER order_type;
ALTER TABLE mall_member ADD COLUMN commission_balance BIGINT NOT NULL DEFAULT 0 COMMENT '佣金余额（分）';
```

**一致性要点（落地时必读）**
- 佣金计算幂等：`UNIQUE(order_id, distributor_id, deleted)`，订单完成通知重复到达直接返回，避免重复计佣。
- 结算时机：监听 `order` 状态 → 已完成才结算；退款时对应 `commission_record` 置 `2 失效`，并回退 `distributor.withdrawable` + `mall_member.commission_balance`（复用 `refund` 状态机钩子）。
- 邀请绑定：注册即绑或首单绑，绑定后不可改（`UNIQUE(invitee_id)`）。
- 防自邀：`apply`/`bind` 时 `inviter == self` 直接拒绝；`parent_id` 不可指向自己。

## 五、接口设计

### C 端（网关路由新增，`/shop/**`）

| 服务 | 路由 | 接口 |
|---|---|---|
| marketing | `/shop/distributor/**` | `GET /shop/distributor/info`（我的状态/邀请码/余额/团队数）· `POST /shop/distributor/apply`（申请）· `GET /shop/distributor/team`（我的团队）· `GET /shop/distributor/commission`（佣金明细）· `POST /shop/distributor/withdraw`（提现申请）· `POST /shop/distributor/bind`（绑定邀请关系，带 `invite_code`） |
| marketing | `/shop/promotion/**` | `GET /shop/promotion/goods`（可推广商品，带佣金标签） |

商品详情 `GET /shop/goods/{id}` 返回体追加 `promotion`（是否可推广、佣金比例、推广价）标志位（登录态）。

### 后台（网关路由新增，`/mall_*`）

| 服务 | 路由 | 接口 |
|---|---|---|
| marketing | `/mall_distributor/**` | `POST /mall_distributor/page` · `POST /mall_distributor/audit` · `POST /mall_distributor/enable` · `POST /mall_distributor/disable` |
| marketing | `/mall_commission_rule/**` | `POST /mall_commission_rule/page` · `POST /mall_commission_rule/save` |
| marketing | `/mall_commission/**` | `POST /mall_commission/page` · `POST /mall_commission/settle`（手动结算，可选） |
| marketing | `/mall_withdrawal/**` | `POST /mall_withdrawal/page` · `POST /mall_withdrawal/audit`（审核打款） |

### 内部契约（`/inner`，不经网关）
| 提供方 | 接口 | 消费方 |
|---|---|---|
| order | `POST /inner/order/distributor-settle`（订单完成通知 marketing 结算佣金） | marketing（结算） |
| member | `POST /inner/point/grant`（已有，提现转增积分可选）· `POST /inner/notice/push`（已有，新邀请/新下级通知）· `POST /inner/member/commission-balance`（新增，扣减佣金余额） | marketing（提现/通知） |
| goods | `POST /inner/goods/promo-tag`（标记推广商品，可选） | marketing（推广） |
| refund | 复用七态状态机钩子，退款完成后回调 marketing 置佣金失效 + 回退余额 | marketing（回退） |
